        Configuration & connection diagnostics
        The dashboard uses server-side service configuration. Refresh interval: 5 seconds. Cloud metrics use a rolling 60-second window and reset on restart.
        Checking connections...
        Hospital queues remain available during Cloud outages. For connection errors, check the service process and Docker health, then refresh. PostgreSQL errors require database connectivity to be restored.
        Manual replay is optional and disabled by default. Local outage authorization is temporary and stays in memory; reload clears it. Use synthetic data only.
        MetaGuard monitoring requires server-side DASHBOARD_CONTROLLER_URL and DASHBOARD_CONTROLLER_TOKEN. Credentials are never entered or displayed here. The default seven-service stack has no controller.
        Run instructions and troubleshooting: see docs/DASHBOARD.md in the repository.
        
      
        
        
        HTTP Response Guide
        
      
        
      
        
        
        
          201 Created
          
        New event successfully applied and stored in PostgreSQL.
        
        
        
        
        
          200 OK
          
        Identical event already exists. No duplicate row is inserted.
        
        
        
        
        
          409 Conflict
          
        A prerequisite is missing, or an existing ID has different data.
        
        
        
        
        
          422 Invalid Input
          
        The event does not satisfy the API's validation rules.
        
        
        
        
        
          503 Unavailable
          
        PostgreSQL is unavailable. Restore connectivity and retry safely.
